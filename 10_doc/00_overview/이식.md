# 이 레포에서 공식 레포로 옮기는 방법

대상: `edu_logic_auditor` (`10_doc` / `20_src` / `90_config` / `91_mig`).

이 브랜치는 그 폴더 이름과 환경 변수 이름을 맞춰 둔 복사본이다. **md만 가져가면 화면이 없다.** 아래 폴더를 통째로 옮긴 뒤, 공식 앱의 기존 화면은 덮어쓰지 않는다.

테스트 앱(`index.html`, `https://nodelab-swart.vercel.app`)은 루트에 그대로 둔다. 공식 Next 앱으로 바꾸려면 `20_src/frontend`만 본다.

## 하지 말 것

- 공식 `20_src/frontend/app/onboarding/` 덮어쓰기 (이미 있는 온보딩)
- 공식 `20_src/frontend/app/admin/` 덮어쓰기
- 공식 `91_mig/supabase/migrations/` 안 기존 SQL 수정
- `public.profiles` ALTER (다른 앱 테이블)
- 공식 `members` / `system_accounts` / `audits` 스키마 변경
- 테스트용 Supabase·GCP·Vercel 키를 공식 프로젝트에 붙여 넣기
- 이 레포 `main`을 공식 `main`에 머지

## 환경 변수 (이름만 맞출 것)

프론트 (`20_src/frontend/.env.local`, Vercel 프로젝트 프론트):

```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
BACKEND_URL=
```

백엔드 (`20_src/backend/.env`, Vercel 프로젝트 API):

```
SUPABASE_URL=
SUPABASE_SERVICE_ROLE_KEY=
DATABASE_URL=
FRONTEND_ORIGIN=
```

값은 **공식 계정으로 새로 만든** GCP OAuth · Supabase · Vercel에서 넣는다. 테스트 앱(`yrgaj…`, `nodelab-swart`)을 재사용하지 않는다.

Google 콜백은 공식 Supabase 프로젝트의  
`https://<project-ref>.supabase.co/auth/v1/callback`  
Site URL은 공식 프론트 도메인. 자세한 키 위치는 `90_config/env/README.md`.

## 화면 순서 (그대로)

0. 랜딩  
1. 로그인 (구글)  
2. 약관 동의 (필수 이용약관 + 필수 개인정보 + 만 14세. 마케팅은 선택. 국외이전은 별도 체크 없음)  
3. 별명·연령대  
4. 온보딩 5선택 (`app/welcome`)  

이미 `nl_profiles`에 `terms_version` + `privacy_version` + `nickname`이 있으면 2–3을 건너뛴다.  
거부하거나 만 14세 미만이면 로그아웃 후 랜딩. 소셜 세션만으로는 회원이 아니다.

## DB

`91_mig` SQL은 `nl_profiles`를 **추가**한다. 공식에 이미 `members`가 있어도 그 테이블은 건드리지 않는다. 회원 SoT를 `members`로 쓸 계획이면 컬럼 의미만 맞추고 테이블 이름은 그쪽에 맞춘다.

SQL 에디터에서 직접 실행해도 되고 `supabase db push`여도 된다. 한 번이면 된다.

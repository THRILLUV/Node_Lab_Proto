# ADR-017: 수식 전용 OCR 모델(pix2tex / Qwen-LaTeX) 도입 타당성 검토 및 멀티모달 LLM 직접 처리 결정

## 상태
확정 (Accepted) - 2026-09-01

## 맥락
멘토링에서 추천된 이미지-LaTeX 변환 전용 오픈소스 모델(pix2tex `LaTeX-OCR`, Hugging Face `clzoro/Qwen3-VL-4B-LaTeX-OCR`)을 NodeLab 파이프라인에 별도로 구축/연동해야 하는지, 아니면 현재의 멀티모달 LLM(Gemini 3.7 Flash) 단일 처리 방식을 유지할 것인지 기술적·경제적 타당성을 검토함.

---

## 1. 전용 LaTeX-OCR 모델 도입 시의 장점 (Pros)

1. **복잡한 수식 전용 특화 인식률**:
   - 3중 중첩 분수, 다차원 행렬 괄호, 희귀 적분 기호 등 극도로 복잡한 수식 기호에 대해 미세한 픽셀 단위 전사 정확도가 높음.
2. **LLM 입력 토큰 절감**:
   - 이미지를 LLM에 직접 보내지 않고 텍스트(LaTeX)로 먼저 바꾼 뒤 텍스트 전용 LLM에 넘기므로 이미지 토큰 비용을 일부 아낄 수 있음.

---

## 2. 굳이 붙이지 않아도 되는 결정적 이유 (Cons & Blockers)

1. **한글 손글씨와 수식이 섞인 실제 학생 풀이 처리 불가 (치명적 한계)**:
   - `pix2tex`나 `Qwen-LaTeX`는 **"순수 영어/수식만 있는 인쇄물이나 정갈한 수식 조각"**만 학습한 모델임.
   - 실제 학생의 손풀이는 *"여기서 $x=3$ 대입하면 $\Sigma$ 분배해야 함"* 처럼 **한글 필기와 수식이 뒤섞여 있음**.
   - 전용 LaTeX-OCR은 한글 텍스트를 만나면 깨지거나 에러를 뱉지만, **Gemini 3.7 Flash는 한글 손글씨 + LaTeX 수식을 완벽하게 동시 해석**함.

2. **GPU 인프라 유지비 및 호스팅 비용 폭탄**:
   - `Qwen3-VL-4B` 같은 모델을 실시간으로 서빙하려면 **전용 GPU 서버(AWS EC2 G5 인스턴스, 월 40~60만 원 이상)**를 상시 켜두어야 함.
   - 반면 Gemini 3.7 Flash API는 서버리스로 호출당 약 2~3원만 과금되므로 **초기 서버 고정비가 0원**.

3. **파이프라인 복잡도 및 응답 지연(Latency) 증가**:
   - 전용 모델 도입 시: `[이미지 ➔ GPU OCR 서버 ➔ 텍스트 추출 ➔ LLM 서버 ➔ 진단]` (네트워크 2회 왕복, 지연 3~4초).
   - Gemini 단일 처리 시: `[이미지 ➔ Gemini 3.7 ➔ OCR + 결손 진단 + 힌트 동시 생성]` (네트워크 1회, 지연 1.2초).

---

## 3. 최종 결정 및 로드맵
* **현재 MVP 및 1차 상용화**: **Gemini 3.7 Flash 멀티모달 단독 처리 유지** (비용 최적, 한글 손글씨 완벽 지원, GPU 서버비 0원).
* **향후 백로그 (2차 고도화)**: 향후 수만 명의 유저가 유입되어 이미지 토큰 비용이 자체 GPU 서버 운영비보다 커지는 시점(월 수천만 건 호출)에 한해 온프레미스 경량 OCR 도입 재검토.
